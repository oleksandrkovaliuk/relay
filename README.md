# Relay — teacher workspace

A desktop workspace for one-to-one English teachers. The teacher app is Electron;
homework is generated by the locally authenticated Claude Code CLI; students do
their homework in a browser; everything is stored in Convex, so the teacher's
inbox updates live.

## The loop

1. **Add a student** with their level, recurring errors, and Miro board. That
   context is stored once and reused forever.
2. **Create homework** — pick the student, type a sentence about today's lesson.
   Claude also receives the student's standing context and the focus areas from
   their previous submissions, so almost no extra notes are needed.
3. **Review and publish.** Drafts are never shared until the teacher publishes.
   Publishing returns a link to the hosted browser player.
4. **The student opens the link** in any browser and works through interactive
   widgets: option cards, inline blanks inside the sentence, click-to-connect
   matching, and free writing.
5. **The teacher's inbox fills in live** with score, engaged time, tab-aways,
   answer revisions, and an optional Claude summary of what to teach next.

## Commands

| Command | What it does |
| --- | --- |
| `pnpm dev` | Convex watcher plus the Electron teacher app |
| `pnpm dev:desktop` | Electron only |
| `pnpm dev:web` | Student player on `localhost:5180` |
| `pnpm check` | Typecheck, tests, and all three builds |
| `pnpm test:live` | Live tests that call the real Claude CLI (consumes quota) |
| `pnpm host:web` | Build the player and upload it to the development Convex deployment |
| `pnpm deploy:web` | Build and deploy the production Convex backend + student player |

## What gets tracked

Per answer: engaged time (paused when the tab loses focus), tab-aways, and the
number of times the answer changed. Per submission those roll up into total
active time and lookups. `dashboard.questionInsights` ranks questions by accuracy
and shows average time, lookup rate, and edits — a correct answer that took 90
seconds and five edits is not the same as one that took 10.

## Architecture notes

- Frontend code is organised in **vertical slices** by the domain that owns it —
  `homework/`, `students/`, `submissions/`, `insights/`, `today/`, `claude/` —
  with `components/ui/` for shadcn primitives and `lib/` for product-agnostic
  helpers. See [docs/architecture/frontend.md](docs/architecture/frontend.md).
- Two aliases cover everything: `@/*` → `src/*` and `@convex/*` → `convex/*`.
- `src/homework/player/homework-wizard.tsx` is the single step-by-step homework
  surface, shared by the student player and both teacher previews.
- `src/renderer/` is the Electron teacher app; `src/web/` is the student player
  built as a standalone static site.
- `src/main/claude/` owns the Claude runtime. Credentials stay in the Claude CLI;
  the Agent SDK is pointed at the installed executable. Output is constrained by
  a Draft-07 JSON Schema derived from the Zod schema in `src/shared/claude.ts`.
- `convex/content.ts` holds the question/answer discriminated unions plus
  grading. `assignments.getPublic` strips every answer key before it reaches a
  student's browser.
- See [docs/architecture/claude-runtime.md](docs/architecture/claude-runtime.md).

## Hosting

The student player is served from the Convex deployment's site domain, so there
is no second hosting provider. `pnpm host:web` uploads to the **development**
deployment. `pnpm deploy:web` performs the coordinated production backend and
player deployment.

Set `VITE_PLAYER_ORIGIN` in `.env.local` to the hosted origin so the teacher app
copies public links rather than `localhost` ones.

See [docs/deployment.md](docs/deployment.md) for the release shape, production
blockers, desktop packaging, and launch checklist.
